Dashboard API Contract

Every endpoint the dashboard calls, what each role may call, and the exact fields that come back — so the screens Paul builds and the server Chidera runs match, view by view.

How to use this. Each dashboard view below lists the endpoints it needs and the fields it reads. If a field here does not match the server, the server is wrong. If a screen needs something not listed, it goes in Gaps at the end, with an owner, rather than being worked around in the browser. The design these views follow is the shareable Risk Radar Desk page.

Rules both sides follow

  • One base path, same origin. Everything is under /v1. In development the Vite server forwards /v1 to the API on port 8000.
  • Sign-in is a cookie. POST /v1/auth/login sets a server-side session in a cookie JavaScript cannot read. Every request sends it (credentials: 'include'); nothing stores a token in the browser.
  • The menu comes from the server. GET /v1/auth/me returns the role's permissions; Paul builds navigation and hides buttons from that list. The server still refuses anything not allowed (403), so hiding is convenience, not security.
  • Money is integer kobo. Any field ending _minor is kobo as a whole number. Divide by 100 only for display; never add money as decimals.
  • Times are ISO 8601 with a time zone. occurred_at is when a payment happened; show that, not when it arrived.
  • Risk levels are words: LOW, MEDIUM, HIGH, CRITICAL. The screen always shows the word as well as the colour.
  • Errors return {"detail": ...}. 401: send to sign-in. 403: this role may not. 404: gone. 409: someone else got there first (for example two analysts taking the same case) — refetch and try again.
  • Advisory only. No endpoint blocks, holds or reverses a payment, and no screen may suggest one does.

What this means for Paul

  • Build the menu and every button from me.permissions; never from the role name.
  • Treat the worklist as the source of truth: refetch on each stream "alert" event and after every action; do not patch the list by hand.
  • Show money from _minor fields only, divided by 100 at the last step.
  • Handle 409 on "take next case" by fetching again; handle 403 by explaining what the role cannot do, not by showing an error.
  • Every risk level, clock and chart state carries a word, not just a colour, using the validated colours in the Desk design.
  • The administrator's screens never link to a case, even by ID.
