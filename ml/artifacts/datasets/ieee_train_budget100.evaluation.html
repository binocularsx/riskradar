How to read this

  • Incidents, not rows. An incident counts as caught if any of its transactions is alerted: one alert opens the case.
  • Ranges overlap, no difference. Two arms whose 95% ranges overlap are not distinguishable on this data.
  • Shipped versus retrained. The shipped model learned a simulated Nigerian bank. A large gap to the retrained arm is expected on foreign data and says the model must be retrained on a bank's own outcomes before it is trusted.
  • No borrowed scores. Columns somebody else computed (scores, risk, flags) were excluded as inputs (D10f).

# Risk Radar dataset mapping (D81) for IEEE-CIS Fraud Detection (Vesta, Kaggle).
# Written 17 Sep 2026 from the published column list, then checked against the
# downloaded files the same day (ml/datasets/join_ieee.py): every mapped column is
# present; train 590,540 rows over 182 days, 3.50% fraud; test 506,691 rows, 30
# days after train ends, no labels. The customer key gives 73,407 customers, half
# with two transactions or fewer, so behavioural history is thin.
#
# What this dataset is: card-not-present e-commerce, with real chargeback labels.
# What it cannot give: account transfers, declines (only processed transactions),
# sign-in or SIM events, credits, destinations. So the rules built for Nigerian
# transfers mostly cannot fire, and the test is mainly of the model and the method.
#
# Choices to check:
# - Time: TransactionDT is seconds from an unstated start; 2017-11-30 is the common
#   reading. Only gaps between transactions matter to the measurements.
# - The customer: the file has no card number. card1 (issuer and card range),
#   addr1 (billing region), P_emaildomain and card_start_day (transaction day minus
#   D1, added by join_ieee.py) are the usual stand-in. Without card_start_day a
#   card range reads as one card and the burst rule fired 20 times a day, all false.
# - Labels: Vesta marks a card's later transactions fraud after a chargeback, so
#   incidents (fraud rows of one card within 24 hours) are the fairer unit.
# - Native features for the ceiling arm: C1-C14 (counts) and D1-D15 (day gaps),
#   Vesta's own engineered columns. V1-V339 are left out: their meaning is not
#   published (D10f: a column whose making cannot be read is not an input).
