How to read this

  • Incidents, not rows. An incident counts as caught if any of its transactions is alerted: one alert opens the case.
  • Ranges overlap, no difference. Two arms whose 95% ranges overlap are not distinguishable on this data.
  • Shipped versus retrained. The shipped model learned a simulated Nigerian bank. A large gap to the retrained arm is expected on foreign data and says the model must be retrained on a bank's own outcomes before it is trusted.
  • No borrowed scores. Columns somebody else computed (scores, risk, flags) were excluded as inputs (D10f).

# Risk Radar dataset mapping (D81). Written by `evaluate_dataset.py suggest`.
# Read every field before running: a wrong sender or label column makes every
# figure meaningless while looking plausible. Then set `reviewed: true`.
# NOTE: no incident column: fraud rows of one customer (and type) within 24 hours count as one incident
# NOTE: `step` is numeric; read as hours. Check the unit: every per-hour measurement depends on it
# NOTE: amounts are multiplied by 100 into minor units (kobo, cents); set `scale: 1` if already minor
# NOTE: no approval/decline column: every row is treated as approved, so decline-based measurements and the card-testing rule cannot fire
# NOTE: `type` values read as credits: ['CASH_IN']
# NOTE: 4 other numeric columns are offered as `native_features` for the comparison arm only; delete any that are derived from the label or from the future
dataset: PaySim mobile money (Lopez-Rojas)
reviewed: true
fields:
  label:
    column: isFraud
    positive:
    - 1
  incident:
    derive:
      by: customer
      gap_hours: 24
  timestamp:
    column: step
    unit: hours
    origin: '2026-01-01T00:00:00+00:00'
  amount:
    column: amount
    scale: 100
  account:
    column: nameOrig
  beneficiary:
    column: nameDest
  auth_result:
    constant: APPROVED
  instrument:
    column: type
    values:
      PAYMENT: ACCOUNT_TRANSFER
      TRANSFER: ACCOUNT_TRANSFER
      CASH_OUT: CASH
      DEBIT: CARD
      CASH_IN: CASH
    default: ACCOUNT_TRANSFER
  direction:
    column: type
    values:
      PAYMENT: OUTBOUND
      TRANSFER: OUTBOUND
      CASH_OUT: OUTBOUND
      DEBIT: OUTBOUND
      CASH_IN: INBOUND
    default: OUTBOUND
